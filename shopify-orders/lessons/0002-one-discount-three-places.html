Shopify Orders · Lesson 02 · Discounts

One discount, three places

Codes, applications, allocations — and the two ways total_discounts will lie to you.

Lesson 01 ended with SAVE10 taking 12.00 off a hoodie. That one discount is written into the payload three times, in three fields with three jobs. Merchants then stack a free shipping code and an automatic promotion on top, and the header numbers stop agreeing with each other. They are not wrong. Each field is answering a different question. This lesson teaches you which question each one answers, using the same order from Lesson 01 with a cap added.

Recall from Lesson 01: subtotal_price is the sum of line values, and a line value is price × quantity − total_discount. Only discounts move the subtotal. Hold that while the discount fields multiply.

The three places

fieldanswerslives on
discount_codeswhich codes did the customer type, and what did each producethe order
discount_applicationswhat rules were applied, in what order, targeting whatthe order
discount_allocationshow much of each rule landed on this lineeach line and shipping line

Shopify calls discount_allocations "an ordered list of amounts allocated by discount applications",1 and each allocation points back to an application by index. The application's index is "an ordered index that can be used to identify the discount application and indicate the precedence of the discount application for calculations".2 Precedence matters in step 8.

Step 6. A second line. The discount splits

Add a Cap at 25.00. SAVE10 has allocation_method: across, so 10% of 145.00 = 14.50 spreads in proportion to line value.

"line_items": [
  { "title": "Hoodie", "price": "60.00", "quantity": 2, "total_discount": "12.00",
    "discount_allocations": [ { "amount": "12.00", "discount_application_index": 0 } ] },
  { "title": "Cap", "price": "25.00", "quantity": 1, "total_discount": "2.50",
    "discount_allocations": [ { "amount": "2.50", "discount_application_index": 0 } ] } ],
"discount_codes": [ { "code": "SAVE10", "amount": "14.50", "type": "percentage" } ],
"total_line_items_price": "145.00",
"total_discounts": "14.50",
"subtotal_price": "130.50",
"total_tax": "17.10",
"total_price": "159.60"

Three things agree here and you should check them every time: the code's amount equals the sum of its allocations across lines; the sum of total_discount equals total_discounts; the sum of line values equals subtotal_price. Tax is 12.96 + 2.70 + 1.44 shipping = 17.10.

Step 7. Free shipping. The first lie

Add FREESHIP. It targets the shipping line, not the products.

"discount_codes": [
  { "code": "SAVE10", "amount": "14.50", "type": "percentage" },
  { "code": "FREESHIP", "amount": "12.00", "type": "shipping" } ],
"discount_applications": [
  { "code": "SAVE10", "target_type": "line_item", "allocation_method": "across" },
  { "code": "FREESHIP", "target_type": "shipping_line", "value": "100.0", "value_type": "percentage" } ],
"shipping_lines": [
  { "price": "12.00", "discounted_price": "0.00",
    "discount_allocations": [ { "amount": "12.00", "discount_application_index": 1 } ],
    "tax_lines": [] } ],
"total_discounts": "26.50",
"subtotal_price": "130.50",
"total_tax": "15.66",
"total_price": "146.16"

Watch what moved and what did not:

  1. subtotal_price stayed at 130.50. Shipping discounts live on the total side of the chain.
  2. total_discounts jumped to 26.50. It mixes product and shipping discounts into one number.
  3. Shipping tax vanished. Tax is charged on discounted_price, now 0.00. Total: 130.50 + 0.00 + 15.66 = 146.16.

This is the first lie: if you subtract total_discounts from anything that already contains shipping, you remove the 12.00 twice. smile-core's normalizer avoids it by subtracting the type: shipping amounts out of total_discounts before touching the merchandise base.4

Step 8. An automatic discount. The second lie

The merchant runs an automatic discount: 5.00 off each hoodie. Shopify applies product discounts first and order discounts "to the revised subtotal after product discounts".3 So the automatic one goes first, then SAVE10 on the reduced prices.

"discount_applications": [
  { "type": "automatic", "title": "Hoodie Season", "value": "5.0", "value_type": "fixed_amount",
    "target_type": "line_item", "target_selection": "entitled", "allocation_method": "each" },
  { "type": "discount_code", "code": "SAVE10", "value": "10.0", "value_type": "percentage",
    "target_type": "line_item", "target_selection": "all", "allocation_method": "across" },
  { "type": "discount_code", "code": "FREESHIP", "target_type": "shipping_line" } ],
"discount_codes": [
  { "code": "SAVE10", "amount": "13.50", "type": "percentage" },
  { "code": "FREESHIP", "amount": "12.00", "type": "shipping" } ],
"line_items": [
  { "title": "Hoodie", "price": "60.00", "quantity": 2, "total_discount": "21.00",
    "discount_allocations": [
      { "amount": "10.00", "discount_application_index": 0 },
      { "amount": "11.00", "discount_application_index": 1 } ] },
  { "title": "Cap", "price": "25.00", "quantity": 1, "total_discount": "2.50",
    "discount_allocations": [ { "amount": "2.50", "discount_application_index": 1 } ] } ],
"total_line_items_price": "145.00",
"total_discounts": "35.50",
"subtotal_price": "121.50",
"total_tax": "14.58",
"total_price": "136.08"
discount_applications line_items[Hoodie].discount_allocations [0] automatic 5.00 each ◀──── { amount 10.00, index 0 } [1] SAVE10 10% across ◀──── { amount 11.00, index 1 } total_discount 21.00 [2] FREESHIP shipping ◀──── shipping_lines[0].discount_allocations { 12.00, index 2 }

The shape changed, not just the numbers:

  1. The automatic discount took index 0. Every other allocation index shifted by one. Never cache indexes across webhooks.
  2. discount_codes does not list it. Its amounts sum to 25.50 while total_discounts is 35.50. The 10.00 gap is the automatic discount. This is the second lie: discount_codes is only what the customer typed.
  3. SAVE10 shrank from 14.50 to 13.50. It applied to 110.00 + 25.00, not 145.00. Whether two discounts stack at all depends on the merchant's combination settings; a customer can enter up to 5 product or order codes and 1 shipping code.3

Hoodie line value: 120.00 − 21.00 = 99.00. Cap: 22.50. Subtotal 121.50. Tax 11.88 + 2.70 = 14.58. Total 121.50 + 0.00 + 14.58 = 136.08.

⚠ What this means for cashback
A per-line base reads price × quantity − total_discount and never touches total_discounts, so both lies are avoided for free. If you ever need the order-wide number, compute it as the sum of line total_discount, not from the header.
