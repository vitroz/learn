Shopify Orders · Lesson 01 · Foundations

The totals chain

Five fields, one hoodie, and the shape every other lesson hangs on.

A Shopify order arrives as forty money fields, and the first instinct is to memorize them. Don't. They are one short chain with a breakdown attached to each link. Once you see the chain, every field tells you which link it belongs to, and the cashback question becomes "which link is my base?" This lesson builds the chain from a single hoodie to the first discount code. Every number reconciles, so check them as you go.

Where you started: you proposed total_price = quantity × price − discounts + tax. Right shape, three gaps: shipping, tips, and the fact that total_discounts hides shipping discounts inside it. By the end of this lesson you will be able to write the correct version from memory.

The one idea

line items ──minus discounts──▶ subtotal ──plus shipping, tax, tip──▶ total │ │ │ │ price × quantity │ never contains tax, │ what the card │ per line │ shipping or tips │ was charged

subtotal_price sits in the middle. Discounts push it down. Nothing else touches it. Tax, shipping and tips only reach total_price.1 When a field confuses you, ask which side of the subtotal it lives on.

The shop for every lesson is the same: British Columbia, 12% tax added on top of prices, shop currency CAD.

Step 1. One hoodie

{
  "line_items": [
    { "id": 1, "title": "Hoodie", "price": "60.00", "quantity": 1,
      "total_discount": "0.00", "tax_lines": [] }
  ],
  "total_line_items_price": "60.00",
  "total_discounts": "0.00",
  "subtotal_price": "60.00",
  "total_tax": "0.00",
  "total_price": "60.00"
}

Every total is 60.00. With nothing else on the order, the whole chain collapses to the price of the one line. Notice that money comes as strings. Never parse them into floats.

Step 2. Quantity 2. Where is the line total?

"line_items": [ { "price": "60.00", "quantity": 2, "total_discount": "0.00" } ],
"total_line_items_price": "120.00",
"subtotal_price": "120.00",
"total_price": "120.00"

There is no line total in the REST payload. price stays the unit price. You compute the line yourself:

line value = price × quantity − total_discount
           = 60.00 × 2 − 0.00 = 120.00

GraphQL gives you originalTotalSet for the first half, and its discountedTotalSet removes only line-level discounts, not order or code discounts.2 The formula above is the one that always holds.

Step 3. Tax at 12%

"taxes_included": false,
"line_items": [ { "price": "60.00", "quantity": 2,
  "tax_lines": [ { "title": "PST+GST", "rate": 0.12, "price": "14.40" } ] } ],
"tax_lines": [ { "title": "PST+GST", "rate": 0.12, "price": "14.40" } ],
"subtotal_price": "120.00",
"total_tax": "14.40",
"total_price": "134.40"

Tax appears twice, once on the line and once rolled up on the order. The subtotal did not move. The total did. taxes_included: false says the 60.00 was net of tax; the tax-inclusive case flips the arithmetic and gets its own lesson.

Step 4. Shipping at 12.00

"shipping_lines": [
  { "title": "Standard", "price": "12.00", "discounted_price": "12.00",
    "tax_lines": [ { "title": "PST+GST", "rate": 0.12, "price": "1.44" } ] } ],
"subtotal_price": "120.00",
"total_tax": "15.84",
"total_price": "147.84"

Shipping has its own price and its own tax line. Shipping tax joins total_tax: 14.40 + 1.44 = 15.84. The subtotal still does not move. There is no plain total_shipping_price string; shipping only exists in the _set form.1

Step 5. A 10% code

"discount_codes": [ { "code": "SAVE10", "amount": "12.00", "type": "percentage" } ],
"line_items": [
  { "price": "60.00", "quantity": 2, "total_discount": "12.00",
    "discount_allocations": [ { "amount": "12.00", "discount_application_index": 0 } ],
    "tax_lines": [ { "rate": 0.12, "price": "12.96" } ] } ],
"total_line_items_price": "120.00",
"total_discounts": "12.00",
"subtotal_price": "108.00",
"total_tax": "14.40",
"total_price": "134.40"

price is still 60.00. The discount landed on the line as total_discount, "the total amount of the discount allocated to the line item".1 Line value: 120.00 − 12.00 = 108.00, which is now the subtotal.

Tax was recomputed on the discounted value: 12% of 108.00 is 12.96, plus 1.44 on shipping. Total: 108.00 + 12.00 + 14.40 = 134.40. That equals step 3 by coincidence, and it is a good reminder that total_price alone says little about what was bought.

Read the subtotal column. It only moved once, at step 5, when a discount entered. Read the total column. It moved every time.

The formulas, in plain words

line value             = price × quantity − total_discount
total_line_items_price = sum of (price × quantity) over all lines
subtotal_price         = sum of line value over all lines
shipping               = sum of discounted_price over all shipping lines
total_tax              = sum of tax_lines.price over all lines and shipping lines
total_price            = subtotal_price + shipping + total_tax + total_tip_received

The reference card keeps these, plus the two traps you will meet in Lesson 02.

⚠ What this means for cashback
Your normalizer picks one link as the base. subtotal_price is the merchandise value after discounts and before anything the merchant does not keep. smile-core's rewardable_total starts from total_line_items_price and works its way down to the same place under default settings.3 Whatever you pick, name the link, not the number.
