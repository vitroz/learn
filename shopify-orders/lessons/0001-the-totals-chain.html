The totals chain

One query, one hoodie, and the shape every other lesson hangs on.

An Order in the GraphQL Admin API exposes dozens of MoneyBag fields, and the first instinct is to memorize them. Don't. They are one short chain with a breakdown attached to each link. Once you see the chain, every field tells you which link it belongs to, and the cashback question becomes "which link is my base?" This lesson builds the chain from a single hoodie to the first discount code, using the exact query you will run in the new normalizer. Every number reconciles, so check them as you go.

Where you started: you proposed total = quantity × price − discounts + tax. Right shape, three gaps: shipping, tips, and the fact that the order-level discount total includes shipping discounts. By the end of this lesson you will be able to write the correct version from memory, in GraphQL field names.

The one idea

line items ──minus discounts──▶ subtotal ──plus shipping, tax, tip──▶ total │ │ │ │ originalTotalSet │ subtotalPriceSet: never │ totalPriceSet: │ per line │ contains shipping or tips │ what was charged

subtotalPriceSet sits in the middle: "the sum of the prices for all line items after discounts and before returns".1 Discounts push it down. Nothing else touches it. Shipping, tax and tips only reach totalPriceSet. When a field confuses you, ask which side of the subtotal it lives on.

The shop for every lesson is the same: British Columbia, 12% tax added on top of prices, shop currency CAD. Every amount below is shopMoney.amount, a Decimal scalar that arrives as a string. Never parse it into a float.

The query

query OrderMoney($id: ID!) {
  order(id: $id) {
    name
    currencyCode
    taxesIncluded
    subtotalPriceSet      { shopMoney { amount } }
    totalDiscountsSet     { shopMoney { amount } }
    totalShippingPriceSet { shopMoney { amount } }
    totalTaxSet           { shopMoney { amount } }
    totalTipReceivedSet   { shopMoney { amount } }
    totalPriceSet         { shopMoney { amount } }
    lineItems(first: 50) {
      nodes {
        id title quantity
        originalUnitPriceSet { shopMoney { amount } }
        originalTotalSet     { shopMoney { amount } }
        discountAllocations {
          allocatedAmountSet { shopMoney { amount } }
          discountApplication { index }
        }
        taxLines { title ratePercentage priceSet { shopMoney { amount } } }
      }
    }
    shippingLines(first: 5) {
      nodes {
        title
        originalPriceSet   { shopMoney { amount } }
        discountedPriceSet { shopMoney { amount } }
        taxLines { ratePercentage priceSet { shopMoney { amount } } }
      }
    }
  }
}

Responses below are trimmed to the fields that change at each step. lineItems and shippingLines are connections, so their items sit under nodes.

    "discountAllocations": [], "taxLines": [] } ] },

"totalDiscountsSet": { "shopMoney": { "amount": "0.0" } },
"totalTaxSet":       { "shopMoney": { "amount": "0.0" } },
"totalPriceSet":     { "shopMoney": { "amount": "60.0" } }

Every total is 60.00. With nothing else on the order, the whole chain collapses to the price of the one line.

Step 2. Quantity 2. Two totals per line, and neither is the one you want

{ "quantity": 2,
  "originalUnitPriceSet": { "shopMoney": { "amount": "60.0" } },
  "originalTotalSet":     { "shopMoney": { "amount": "120.0" } },
  "discountAllocations": [] },
"subtotalPriceSet": { "shopMoney": { "amount": "120.0" } },
"totalPriceSet":    { "shopMoney": { "amount": "120.0" } }

originalTotalSet is "the total price of the line item when the order was created. This value doesn't include discounts".2 The line also offers discountedTotalSet, which sounds like what you want and is not: it "doesn't include order-level discounts", and "code-based discounts aren't included by default".2 The value after every discount is something you compute:

line value = originalTotalSet − sum of discountAllocations.allocatedAmountSet
           = 120.00 − 0.00 = 120.00

There is also no order field for "all line items before discounts". You get it by summing originalTotalSet over the lines.1

Step 3. Tax at 12%

"taxesIncluded": false,
"lineItems": { "nodes": [ { "originalTotalSet": { "shopMoney": { "amount": "120.0" } },
  "taxLines": [ { "title": "PST+GST", "ratePercentage": 12.0,
                  "priceSet": { "shopMoney": { "amount": "14.4" } } } ] } ] },
"subtotalPriceSet": { "shopMoney": { "amount": "120.0" } },
"totalTaxSet":      { "shopMoney": { "amount": "14.4" } },
"totalPriceSet":    { "shopMoney": { "amount": "134.4" } }

Tax lives on the line as taxLines, whose priceSet is "the amount of tax, after discounts and before returns",3 and rolls up into totalTaxSet. The subtotal did not move. The total did. taxesIncluded: false says the 60.00 was net of tax; the tax-inclusive case flips the arithmetic and gets its own lesson.

Step 4. Shipping at 12.00

"shippingLines": { "nodes": [
  { "title": "Standard",
    "originalPriceSet":   { "shopMoney": { "amount": "12.0" } },
    "discountedPriceSet": { "shopMoney": { "amount": "12.0" } },
    "taxLines": [ { "ratePercentage": 12.0, "priceSet": { "shopMoney": { "amount": "1.44" } } } ] } ] },
"totalShippingPriceSet": { "shopMoney": { "amount": "12.0" } },
"subtotalPriceSet":      { "shopMoney": { "amount": "120.0" } },
"totalTaxSet":           { "shopMoney": { "amount": "15.84" } },
"totalPriceSet":         { "shopMoney": { "amount": "147.84" } }

A shipping line has two prices, "without any discounts applied" and "after applying discounts",4 and its own tax lines. Shipping tax joins totalTaxSet: 14.40 + 1.44 = 15.84. The subtotal still does not move.

Step 5. A 10% code

"lineItems": { "nodes": [
  { "quantity": 2,
    "originalTotalSet": { "shopMoney": { "amount": "120.0" } },
    "discountAllocations": [
      { "allocatedAmountSet": { "shopMoney": { "amount": "12.0" } },
        "discountApplication": { "index": 0 } } ],
    "taxLines": [ { "ratePercentage": 12.0, "priceSet": { "shopMoney": { "amount": "12.96" } } } ] } ] },
"totalDiscountsSet": { "shopMoney": { "amount": "12.0" } },
"subtotalPriceSet":  { "shopMoney": { "amount": "108.0" } },
"totalTaxSet":       { "shopMoney": { "amount": "14.4" } },
"totalPriceSet":     { "shopMoney": { "amount": "134.4" } }

originalTotalSet is still 120.00. The discount arrived as a DiscountAllocation, "the final calculated discount amount applied to each line".5 Line value: 120.00 − 12.00 = 108.00, which is now the subtotal.

Tax was recomputed on the discounted value: 12% of 108.00 is 12.96, plus 1.44 on shipping. Total: 108.00 + 12.00 + 14.40 = 134.40. That equals step 3 by coincidence, and it is a good reminder that totalPriceSet alone says little about what was bought.

The formulas, in plain words

line value          = originalTotalSet − sum of discountAllocations.allocatedAmountSet
lines before disc.  = sum of originalTotalSet over all lines
subtotalPriceSet    = sum of line value over all lines
shipping            = sum of discountedPriceSet over all shipping lines
totalTaxSet         = sum of taxLines.priceSet over all lines and shipping lines
totalPriceSet       = subtotalPriceSet + shipping + totalTaxSet + totalTipReceivedSet

The reference card keeps these, plus the two traps you will meet in Lesson 02.

⚠ What this means for cashback
Your normalizer picks one link as the base. The line value above is the merchandise value after every discount and before anything the merchant does not keep, and it is per line, so exclusions and partial refunds stay simple. smile-core's current normalizer works from the REST payload and reaches the same place under default settings;6 the new one queries GraphQL, so the field names in this lesson are the ones you will type.

No field sums line items before discounts; originalTotalPriceSet is "the total price of the order at the time of order creation".

  3. Shopify — TaxLine. priceSet: "the amount of tax, in shop and presentment currencies, after discounts and before returns".
  4. Shopify — ShippingLine. originalPriceSet: "the shipping price without any discounts applied"; discountedPriceSet: "the shipping price after applying discounts". Both include tax when taxesIncluded is true.
  5. Shopify — DiscountAllocation. "While DiscountApplication captures the discount's intentions and rules, the DiscountAllocation object shows the final calculated discount amount applied to each line."
